On 3 November, security firm Glow published research showing AI coding agents installing deprecated MCP servers that nobody patches. In 98% of the sessions it studied, the agent picked the outdated package from memory. The user never asked for it. I checked the npm registry on 5 November: 11 of the 15 official @modelcontextprotocol server packages I looked up now carry a deprecation notice. If an agent has ever set up MCP for you, one of them may be in your config. This note gives you a 10-minute audit, a rule for each server you find, and a checker that reads your config for you.

Key takeaways

  • Glow found the deprecated packages downloaded more than 17.3 million times from npm since July 2025, with four high-severity flaws that will never get a patch.
  • One command finds every config that uses them, and npm view <package> deprecated confirms each one in seconds.
  • Switch to the service owner's server where one exists, remove the rest, and pin an exact version on everything you keep.

01What did the MCPhantom research find?

Glow reviewed transcripts of real AI coding sessions in which a deprecated MCP server was installed or suggested, and named the pattern MCPhantom. Help Net Security reported the findings on 3 November 2026:

  • The agent chose the package. In 98% of those sessions the package name came from the model's training data. In 2%, the user asked for the old package by name.
  • It happened everywhere. Glow saw it across Claude Code, Cursor, Codex CLI, Claude Cowork and Claude chat, with models from Anthropic, OpenAI and xAI. Asked to "set up a GitHub MCP", one agent installed the archived reference server instead of GitHub's own.
  • Warnings did not stop it. In one session the agent checked npm, saw the deprecation notice, installed the package anyway and did not tell the user.
  • The flaws stay open. Glow found four high-severity vulnerabilities in the deprecated reference servers. The worst, in the Puppeteer server, lets a prompt injection make the agent run commands an attacker chooses. The maintainers closed the report because the server is archived. No exploitation had been seen when the research was published.

The archive itself is explicit. The servers-archived repository says it is "no longer maintained" and that no security updates or bug fixes will be provided. Seven reference servers remain active in the main repository: Everything, Fetch, Filesystem, Git, Memory, Sequential Thinking and Time.

03The 10-minute MCP server security audit

Run these in order. Each step narrows the list for the next.

  1. Find every config (2 minutes). MCP settings live in different files for each tool: Claude Desktop, Claude Code, Cursor, VS Code and per-project files. Search them all at once on macOS or Linux:
    grep -rl --include='*.json' -e '@modelcontextprotocol/server-' -e 'mcp-server-' ~ 2>/dev/null
    Repeat it inside each code folder you keep outside your home directory. On Windows, run the same search in PowerShell with Select-String.
  2. Check each package (3 minutes). Paste each file into the checker below, or run npm view <package> deprecated for anything it does not recognise. A server with no package name, such as a local script or a url entry, needs a different question: who runs it, and when did it last ship?
  3. Decide each server (3 minutes). Use the rules in the next section.
  4. Close the door (2 minutes). Tell your agents they need approval to add an MCP server. That is a Tier 2 action under the four permission tiers for AI agents: it installs code that runs with your credentials, and it can take far more than 5 minutes to undo.

04What to do with each deprecated MCP server

What you findDecisionWhy

Archived, not used in the last 30 daysRemove itUnused code with open flaws is all risk and no return
Archived, you need it, no owner serverFork it, pin it, own the patchesSomebody has to maintain it, and the original maintainers have stopped

A token typed straight into the configMove it to an environment variableConfig files get copied, synced and shared with agents

For any browser or database server you keep, scope it down as well. Give a database server a read-only user. Put a browser server's tools at Tier 2, because a web page it reads can carry a prompt injection, which is the route the Puppeteer flaw uses.

06Make MCP part of your software inventory

Glow's write-up notes why security tools miss this. Endpoint tools see a trusted Node process installing a package. Dependency scanners have no manifest to read, and the flaws carry no CVE numbers. The fix is to treat each MCP server as a dependency with an owner: one approved server per service, an exact version, a check against the registry's deprecation status before approval, and the same audit every quarter.
